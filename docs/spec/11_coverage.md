# 11. Покрытие крайних случаев: EC -> тест -> этап

## 1. Назначение

Каждый EC из `07_edge_cases.md` обязан иметь хотя бы один автоматический тест, а каждый упомянутый тест должен существовать в коде с маркером. Таблица §3 — состояние спецификации (на M0 все тесты «запланированы»); после M6.3 таблица перегенерируется `make ec-report` и колонка «Статус» показывает фактическое наличие.

## 2. Инструмент `backend/tools/eccheck`

Go-программа (только стандартная библиотека), запускается `go run ./tools/eccheck` из `backend/`.

Флаги:

| Флаг | Значение |
|---|---|
| `-spec` | путь к `docs/spec/07_edge_cases.md` (по умолчанию `../docs/spec/07_edge_cases.md`) |
| `-roots` | каталоги поиска маркеров, через запятую (по умолчанию `.,../web/src,../web/e2e`) |
| `-soft` | печатать отчёт, код выхода 0 (до M6.3) |
| `-markdown` | вывести таблицу §3 с колонкой «Статус» |

Алгоритм:

1. Разобрать строки таблиц спеки, начинающиеся с `| EC-`: ID из первой колонки, тесты — все `T-[A-Z]+-\d+` из последней колонки.
2. Ошибка спеки (всегда фатальна, даже с `-soft`): строка EC без тестов; дубликат ID EC; ID не по формату.
3. Собрать маркеры в коде: в `*_test.go` строки `^\s*// Test-ID: (T-[A-Z]+-\d+)\s*$`; в `*.test.ts`, `*.test.tsx`, `*.spec.ts` — `\[(T-[A-Z]+-\d+)\]` внутри первого аргумента `it(`, `test(`, `describe(`. Каталоги `node_modules`, `testdata`, `gen` пропускаются (кроме фикстур самотеста, которые передаются явно).
4. Для каждого EC: статус `covered`, если все его T найдены; `partial`, если часть; `missing`, если ни одного. Строгий режим: код выхода 1 при любом `partial`/`missing` с перечнем.
5. Предупреждение (не ошибка): маркер T в коде, не упомянутый ни в одном EC и не входящий в список сценарных тестов (`T-I-50`, `T-A-30`) — вероятно опечатка.
6. Отчёт: число EC, число T, число найденных маркеров, список проблем.

Самотест T-CI-05 (`main_test.go`) на `testdata/`: спека с EC без теста (ошибка спеки), код без маркера (missing), маркер в Vitest-файле (covered), опечатка маркера (предупреждение).

`make ec-check` входит в `make ci-go` (мягкий до M6.3, строгий после).
