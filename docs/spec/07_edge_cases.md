# 07. Каталог крайних случаев (EC)

Каждая строка = минимум один автоматический тест. Колонка «Тест» содержит идентификаторы из `08_testing.md`. Тест, который нельзя написать, означает, что строку надо переформулировать, а не оставить без теста. Проверка — `tools/eccheck` (`11_coverage.md`).

Уровни: T-U unit (домен, use case с фейками), T-I integration (настоящий Postgres), T-ISO изоляция тенантов, T-A API (HTTP через `httptest` + настоящий Postgres), T-W фронт (Vitest), T-E e2e (Playwright), T-ARCH архитектура и линтеры, T-CI инфраструктурные проверки.

Номера EC стабильны: новые случаи добавляются в конец (следующий свободный номер EC-144), удалённые помечаются «снят» с причиной, номер не переиспользуется. Поэтому внутри группы номера могут идти не подряд.

Обозначения: «A» и «B» — две несвязанные ветки (два узла `partner` под корнем), актор A — пользователь с ролью только в ветке A.
