## Deviations
- `idempotency_key_reused` is 422 (table of 03 section 2.3 and `errors.go`), not 409.
- A transfer checks the source node first: a viewer sending from its own unit to an invisible unit gets 403 (the source), not 404; an invisible source is 404. Neither tells anything about the destination.
- A cursor is also bound to the reader (my addition to the scope and filters of 03 section 3): a cursor passed to another user is `invalid_cursor` even for the same scope.
- The cursor is checked before the scope is looked up, so a bad cursor on a foreign scope is 400 `invalid_cursor`, not 404 (nothing about the scope leaks).
- A body field with a malformed UUID (`fromNodeId`) is `validation_failed` (generic body decoding), a path or query one is `invalid_id`.
- Operation `kind` and audit `action` are not enum-checked by the generated binding; the use case does it (400 `validation_failed`, field `kind`/`action`).
- Every role holds `operation.read`, so no actor can see a node and lack the right; mutation (f) therefore shows up as 200 with an empty page (RLS hides the foreign scope) instead of 404.
