## Gate in T-I-24 (choice)
No production hook and no `export_test.go` entry. The test wraps `port.BalanceRepo` (`gatedBalances`) and builds two `Transfer` use cases, one per goroutine. After the FIRST `LockForUpdate` of a transaction the wrapper waits (`meeting.wait`) until the other transaction has taken its first lock too, or until a backend of this database is queued on a row lock (`pg_locks`: ungranted `transactionid` plus the tuple lock of that backend; this is what a correct order produces, the second transaction waits for the first lock), or until a 5 s cap. Correct order: no extra delay (the whole test is about 0.6 s). Parameter order: both transactions hold one lock each and ask for the other, deadlock detected by PostgreSQL after `deadlock_timeout`, the test fails in repetition 0 every time. The SQL against `pg_locks` needs no extra privileges (tb_owner works).
