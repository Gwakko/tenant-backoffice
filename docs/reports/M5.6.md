## Findings

- Not defects of the application:
  - Enter in the password field did not submit the form when sent by the browser automation tool. The form is a real `<form onSubmit>` with a submit button, a programmatic submit reached the API (`POST /auth/login`, 200), and the application tests cover submission with `{Enter}` (`login.test.tsx`).
  - The browser extension intermittently refused clicks ("Cannot access a chrome-extension:// URL of different extension"). Working in a fresh tab or through scripted form filling avoided it.
- Fixed in this milestone: the home page text "The node tree arrives in the next milestone" (M5.5); the component tests no longer depend on a developer's `.env` (`testkit.ClearConfigEnv`).

## Known nits (not fixed)

- The audit table scrolls horizontally inside its card when "Changes" holds long JSON; it wraps long lines but the column is wide.
- The seed loads no audit rows, so the Audit tab is nearly empty until the application is used.
- The transfer recipient picker shows one page of 50 children without "Load more".
- The report summary has no `kind` filter, no `includeInactive` switch, and the audit view has no node selector.
- Signing out in one tab is not propagated to other tabs.
