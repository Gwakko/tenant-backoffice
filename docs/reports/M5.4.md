# Отчёт M5.4: карточка узла (обзор, настройки, участники, операции баланса)

## Сделано

- Маршруты: `web/src/routes/nodes.$nodeId.tsx` (layout: табы Overview, Settings, Members, защита `requireSession`, экран «Not found or no access» на 404), `nodes.$nodeId.index.tsx`, `nodes.$nodeId.settings.tsx`, `nodes.$nodeId.members.tsx`. Табы Operations, Reports, Audit добавит M5.5 в layout (маршрутов для них ещё нет, типизированный `Link` на них не собрался бы).
- `lib/money.ts`: `parseMoneyInput` (строки и `BigInt`, `Number`/`parseFloat` нет; ошибки `empty`, `invalid_format`, `too_many_decimals`, `too_large`), `formatMinor`, `minorToInput`, `MAX_MINOR`. `lib/idempotency.ts`: `createAttemptKey` (ключ на попытку: тот же ключ при том же запросе, новый при изменённом запросе и после успеха), `newIdempotencyKey` (`crypto.randomUUID`).
- `features/node` (обзор, диалоги создания ребёнка, переименования, активации/деактивации, удаления, `NodeNotFound`, `SettingsPanel`), `features/members` (список «Direct» / «Including inherited», добавление, смена роли, снятие), `features/balance` (`BalancePanel`, `OperationDialog` для credit/debit/transfer, `RecipientPicker`).
- Общие UI-примитивы `components/ui/{Button,Alert,TextField,SelectField,Dialog,EmptyState}.tsx`: `label`/`htmlFor`, `aria-invalid`, `aria-describedby`, ошибки в `role="alert"` с `aria-live`, успех `role="status"`, `aria-busy` на кнопке, `Dialog` на нативном `<dialog>` (`showModal`, Escape, `aria-labelledby`), содержимое диалога монтируется только в открытом состоянии (каждое открытие = чистая форма и новая попытка).
- Общие модули вне моих списков, нужные для работы (новые файлы, чужие не правились): `api/result.ts` (`ApiError`, `unwrap`, `unwrapEmpty`, `problemOf`; M5.3 им уже пользуется), `api/resources.ts` (чтения `me`, узел, права, баланс, дети; `parentIdOf` по `breadcrumbs`, `can`), `hooks/useApi.ts` (клиент из контекста роутера), `hooks/useAction.ts` (одно действие за раз, на 403 перезапрашиваются только права), `hooks/fieldErrors.ts` (ошибки полей в форму), `test/nodeBackend.ts` (MSW-бэкенд для тестов, `harness.ts` не тронут).
- Сценарии: родитель из `breadcrumbs`, а не из `parentId` (у корня доступа он `null`); «Delete» по правам на родителе и не показывается у корня доступа; тип ребёнка только допустимый по иерархии (`unit` детей не имеет); имя 1..100 после trim; на 403 Alert «You do not have permission for this action.», кэш данных не трогается, `['perms', id]` перезапрашивается; на 404 экран «Not found or no access» (ссылка на первый корень доступа, `['me']` перечитывается, префикс `['children']` инвалидируется); 429 показывает `Retry-After` (через `describeProblem`); сеть/5xx на операции баланса: Alert с кнопкой «Retry» (тот же ключ).
- Операции баланса: ключ создаётся при открытии диалога, переиспользуется при двойном клике и повторе, меняется при изменённой сумме/комментарии/получателе (иначе сервер дал бы 422 `idempotency_key_reused`), сбрасывается после успеха; ответ с `Idempotent-Replayed: true` показывается как обычный успех; кнопка `busy` на время запроса плюс защита в `useAction` (ref, нужна, потому что валидация RHF асинхронна). После успеха инвалидируются `['node', id]`, `['balance', id]` (и получателя перевода), `['children', parentId]`, префиксы `operations`, `audit`, `report-summary`, `report-children`; оптимистичных обновлений нет.
- Участники: селект ролей и строки управления только для ролей не выше своей (`features/members/roles.ts`); строки с унаследованной ролью и роль выше своей без управления; пароль: `type=password`, `autocomplete=new-password`, длина 12..128 байт, поле очищается после любого исхода, в тело уходит только при непустом, в URL и в консоль не попадает (тест).
- Настройки: источник значения `own` / `inherited from <name>` (имя только из `breadcrumbs` узла) / `inherited` (источник `null` или предок выше корня доступа, EC-143); значение `max_operation_amount` вводится как деньги и уходит строкой минимальных единиц; ошибки сервера по полю `value` попадают в форму; «Reset to inherited» только у собственного значения.

## Не сделано / ограничения

- Перевод: получатель выбирается обходом поддерева (`GET /nodes/{id}/children`: открыть ребёнка, подняться на уровень вверх по `breadcrumbs`, поиск по имени среди детей текущего уровня), а не вводом идентификатора (так просили в задаче; `06` §3 говорит про ввод id и проверку `GET /nodes/{id}`, расхождение описано ниже). Глобального поиска по всему поддереву нет (в API его нет).
- «Load more» у списка детей в пикере нет (страница 50); у участников есть.
- Права получателя клиент не знает: ошибки 403/404 по получателю показываются сообщением сервера.
- Табы Operations, Reports, Audit: M5.5.

## Отклонения от спеки

1. `06` §3 (перевод): вместо поля с id получателя выбор из дерева (по решению в задаче). Строку спеки надо обновить.
2. Кнопки в диалоге операции называются «Confirm credit/debit/transfer», кнопки панели «Credit/Debit/Transfer» (открывают диалог). Иначе у «Debit» было бы два одноимённых элемента на экране. «Двойной клик Debit» из T-W-04 = двойной клик «Confirm debit».
3. Ключ идемпотентности привязан к «отпечатку» запроса: при изменении суммы после ошибки берётся новый ключ (спека 06 §5 говорит только про «ту же попытку»).
4. `features/*` берут API-клиент из контекста роутера (`useRouteContext({ from: '__root__' })`), потому что `routes` им импортировать нельзя.
5. Выход после удаления узла: переход на родителя (из `breadcrumbs`), у корня доступа удаление недоступно.

## Как подключён `MoveNodeDialog`

`features/node` не импортирует `features/tree`. `NodeOverview` принимает проп `renderMoveDialog({ open, onClose })` и показывает кнопку «Move» (право `node.move`, не у `platform`), только если проп передан. Маршрут `routes/nodes.$nodeId.index.tsx` (routes может импортировать любые features) передаёт `MoveNodeDialog` из `@/features/tree` (интерфейс `nodeId`, `open`, `onClose`). Заглушка не понадобилась: `features/tree/index.ts` уже существовал при сборке. Тест «the Move button opens the dialog supplied by the route» проверяет связку на реальном `MoveNodeDialog`.
