## Как готовится чистая база

`make e2e` не трогает базу разработки. Порядок: очистка (на случай остатков прошлого прогона), `db-bootstrap` + `migrate` + `seed` + `up` с `TB_DB_NAME=tb_e2e` (создаётся отдельная БД в compose-Postgres, миграции, демо-данные, `api` и `web` поднимаются на ней), удаление `web/playwright-report` и `web/test-results`, `docker compose --profile e2e run --rm -T playwright npx playwright test`. Уборка в `trap ... EXIT` (срабатывает и при падении тестов, проверено временным падающим тестом): `docker compose rm -sf playwright web api` и `DROP DATABASE IF EXISTS tb_e2e WITH (FORCE)`. Postgres не останавливается. Побочный эффект: контейнеры `api` и `web` стека разработки заменяются и после прогона удалены (поднять заново: `make up`).

Независимость тестов: каждый тест создаёт СВОИ узлы и СВОИХ пользователей через API владельца (имена с случайным суффиксом) и не меняет демо-дерево; общего состояния и порядка нет, `serial` не используется. Исключение по данным: T-E-02 переносит свой новый узел под Partner Beta (демо-узлы не двигаются), T-E-01/04/06 только читают демо-данные. Один воркер из-за лимитов API (вход: 5 в минуту на пару e-mail и адрес, 20 на адрес).

## Отклонения и находки

1. Приложение не работает по простому HTTP на имени сервиса: `crypto.randomUUID()` (`web/src/api/client.ts` для `X-Request-Id`, `web/src/lib/idempotency.ts`) недоступен вне защищённого контекста, вход даёт «Cannot reach the server». Для e2e внутри сети compose (`http://web:8080`) Chromium запускается с `--unsafely-treat-insecure-origin-as-secure=<baseURL>` (только origin тестируемого стека) и `channel: 'chromium'` (в headless-shell флаг не действует; проверено: `isSecureContext` false -> true). Код приложения не менялся. Рекомендация: запись в спеку (ниже) и, при желании, fallback генератора идентификаторов в M6.5.
2. T-E-02: после переноса дерево не раскрывает нового родителя само (узел исчез из старого родителя сразу, у нового виден после «Expand Partner Beta»). Тест проверяет именно это; это поведение M5.3, не дефект.
3. Спека `08` §5 говорит `make e2e` = `up` + `make seed` на базе разработки; сделано через отдельную БД `tb_e2e` (повторяемость).
4. Трассировки при падении содержат сетевые ответы страницы, в том числе короткоживущий access-токен демо-стека (10 минут, БД удаляется после прогона). Тесты токены не печатают, API-вызовы подготовки идут через контексты, не попадающие в трассировку. Полностью исключить токены из trace Playwright не позволяет; если нужно строго, поставить `trace: 'off'`.

## Что нужно раннеру для M6.2

Спека `08` §5 уже верна, уточнения:
1. `make keys`; `docker compose up -d --build --wait postgres api web` (web на `127.0.0.1:${TB_WEB_HOST_PORT}`, по умолчанию 8088); `make seed` (через compose, без `-force` на чистой БД).
2. Node 24: `cd web && npm ci`; `cd web && npx playwright install --with-deps chromium` (нужен полноценный chromium: конфиг использует `channel: 'chromium'`; версия браузера определяется `@playwright/test` 1.65.1).
3. `E2E_BASE_URL=http://127.0.0.1:8088 make e2e-inner` (переменная обязательна, значения по умолчанию нет). Адрес `127.0.0.1` задаётся в workflow, не в исходниках `web/`.
4. При падении загружать `web/playwright-report` (и `web/test-results`) как артефакт. Стек поднимается на `tenant_backoffice` из `.env`; отдельная БД нужна только локально. Перед повторным запуском на том же стеке перезапустить `api` (лимит входа 5 в минуту на пару).
5. Задание `e2e` ставит `needs: ci`; `make ci-inner` в нём не нужен.
