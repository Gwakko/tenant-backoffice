- `api/openapi.yaml`: the three response headers `SetCookie` renamed to `Set-Cookie` (login, refresh, logout). The key is the HTTP header name; the generated code wrote a header literally called `SetCookie`, so no cookie reached the client. Matches 03/02 (cookie `tb_refresh`). `make gen` run, `gen/api.gen.go` differs only in these header names; `make gen-check` ok, `openapi_test.go` green.
- `middleware.go`: `reqState.client` field; `server.go`: `capture(...)` middleware added after `routing` (new `transport.go`): client address, user agent, refresh cookie value, CSRF flag, because the generated request objects do not carry cookies or the undeclared CSRF header.
- `usecase/auth`: `Deps.Profile` (`port.ProfileRepo.OwnEmail`, implemented by `postgres.AuthUserRepo`), `RefreshOutput` got `Email` (the token response needs `user.email`), new `profile.go` (`GetProfileUseCase` for `GET /me`, which needs the email; node use cases do not know it). `NewRefreshUseCase` now requires `Profile`; fakes and `postgres/refresh_test.go` updated.
