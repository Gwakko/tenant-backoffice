## Done
- `backend/internal/adapter/httpapi/server.go`: `NewServer(Options)` builds `/healthz`, `/readyz` (existing `HealthHandler`) and `/api/v1` over `gen.NewStrictHandlerWithOptions`. Operations not listed in `Options.Implemented` (nothing yet) answer 501 `not_implemented` through a strict middleware; the generated health routes are skipped (the service serves them itself). Unknown paths give a problem+json 404 `not_found` (no routing details).
- `middleware.go`, chain (outermost first): request id, access log, recover, routing (finds the route template before any decision), body limit (reads at most 64 KiB into memory: 413), Content-Type (415 for a non-JSON body; charset only utf-8), authn, rate limit, Idempotency-Key check (credits, debits, transfers), body shape check (unknown fields, number in `amount`).
  - request id: incoming accepted only if `^[A-Za-z0-9-]{8,64}$`, else a UUID; also `X-Content-Type-Options: nosniff` and `Cache-Control: no-store` on every answer.
  - access log (slog): method, route template (not the concrete path, not the query), status, `duration_ms`, `request_id`, `actor_id`. No body, no headers, no tokens.
  - recover: panic -> 500 `internal` without details; panic text and stack go to the log with `request_id`; `http.ErrAbortHandler` is re-panicked.
  - authn: `Authorization: Bearer`; absent -> `token_missing`, any other malformed form -> `token_invalid`; verification and the database check (`user exists, active, token_version == tv`) are the existing `auth.AuthenticateUseCase` (`Authenticator` interface); rights are never read from the token. 401 carries `WWW-Authenticate: Bearer`.
  - rate limit: login by client address (20/min) and by (address, sha256 of the normalized email) (5/min); refresh by address (20/min); everything else per user: mutations 60/min, reads 600/min (separate buckets). 429 `rate_limited` + `Retry-After` (seconds, rounded up). IPv6 is reduced to its /64. Behind a proxy `TB_HTTP_TRUST_FORWARDED_FOR=true` uses the last `X-Forwarded-For` entry (default off).
- `errors.go`: the only `apperr.Code -> HTTP` mapping (table of 03 section 2.3, both directions checked by `TestErrorMappingTable`, which parses the spec table and the apperr constants). Problem body `type, title, status, code, detail, errors[], requestId`. The `detail` is a fixed text per code, never the error message: raw DB errors, panics and unmapped codes become 500 `internal` with a generic detail (cause only in the log with `request_id`); 404 for a missing and for a foreign object is byte-identical except `requestId` (the use case message is ignored); the three login failures are identical. Generated binding errors: UUID parameters -> `invalid_id`, a missing Idempotency-Key -> `idempotency_key_required`, others -> `validation_failed` with `errors[]`.
- `cursor.go`: `CursorCodec` (`v`, `k`, `f`, `e`): `base64url(JSON) "." base64url(HMAC-SHA256)`; `f` = sha256 of canonical JSON of (scope, filters); expiry `e` (Unix s, `TB_CURSOR_TTL`, default 1h); two keys (`TB_CURSOR_KEY` signs, `TB_CURSOR_KEY_PREVIOUS` still verifies); `hmac.Equal` and `subtle.ConstantTimeCompare`, every key tried without early exit; unknown payload fields, other version, other filters/scope, expiry, length > 2048: all `invalid_cursor` (same message). `ParseLimit` (1..200, default 50).
- `idempotency.go`: `RequestHash(Fingerprint{Method, Route, PathParams, Body})` returns the 32 bytes for `RequestHash` of the balance use cases: `sha256(METHOD "\n" route "\n" sorted path params "\n" canonical JSON)`; canonical JSON has sorted keys, no whitespace, `amount` strings without leading zeros. `ParseIdempotencyKey` (required, one value, `^[A-Za-z0-9_\-:.]{1,128}$`).

## Deviations from the specs
1. Rate limiter is a small own token bucket, not `golang.org/x/time/rate`: injected clock for deterministic tests, a hard key cap and idle-key sweep, no new dependency. Behaviour is the same (burst = limit, refill limit/minute).
2. Middleware order: access log sits outside recover (so it records the 500 of a panic), the spec lists recover first.
3. Cross-adapter rule (T-ARCH-01): `httpapi` cannot import `ratelimit` or `authn`, so `httpapi` owns the `Limiter` and `Authenticator` interfaces; the real stack is tested in `internal/app` (composition root), and `ratelimit.Memory` satisfies `httpapi.Limiter` structurally.
4. `RequestHash` input is `sha256(METHOD "\n" route "\n" "k=v,..." "\n" canonical body)`; a parameter containing `\n`, `=` or `,` is refused so the text stays unambiguous. `03` section 4 says "path params" without a format.
5. Cursor payload has an expiry `e` (not in `03` section 3); `f` covers scope and filters as `03` says.
6. Field errors: `errors[].code` is the code of the error itself and `message` is the short per-field token from `apperr.Error.Fields` (for example `required`), because `Fields` is `field -> token`. Human texts per field are not available from the domain.
7. `not_implemented` (501) is a transport placeholder outside the OpenAPI `ErrorCode` enum; it disappears when M4.3/M4.4 implement all operations.
8. Unknown method on a known path gives 404 `not_found`, not 405 (a catch-all route answers).
9. `limit` and the report parameters are validated by handlers (`ParseLimit` is provided); the strict decoder does not enforce schema ranges.
