## Deviations from the spec
- `apperr.NotFound("node")` of spec 02 section 5.1 is `apperr.NotFoundError("node")` (and `ForbiddenError`, `UnavailableError`): `NotFound` is already the name of the error code constant, as for the other codes.
- `port.Tx` is an interface with the marker method `TxMarker()` (spec: "marker") so that an arbitrary value cannot be passed.
- Repository interfaces live in `usecase/port` (task text), not in the future use case packages (spec 04 section 0 says "in the consumer package"); M2.5 can alias them.
- 23514 and 23503 are mapped to `not_found` for every node write, not only for an insert under an invisible parent (as the task states); a genuine check violation of a visible, well-formed write would also be reported as `not_found`, with the real SQLSTATE and message in the `error` log. A savepoint could separate the two; not done to keep the adapter simple.
- `Node.AncestorsActive` of an INACTIVE access root cannot be derived: the ancestors above it are hidden and `tb_node_effective_active` reports only the combined value. The repository returns `false` (safe) in that one case. A correct value needs a new SECURITY DEFINER function, which the task forbids; to decide in M2.5 (EC-20: activation of such a root shows `EffectiveActive=false`). Covered by `TestRepositoriesRoundTrip/activity of ancestors`.
- `CountChildren` of a hidden parent returns the number of children the actor can see (for the root above an access root: the own branch), not 0. Harmless (use cases `Require` first) and noted in the port comment; the T-ISO-11 test skips the root for this call only.
- New test id T-U-40 added to `08_testing.md` and linked to EC-45 and EC-54 (the use case level of 404 vs 403 had no unit test); `11_coverage.md` updated.
- `TxRunner.InTx` rejects a zero `ActorID` before opening a transaction.
- Spec 02 section 5.3: connection loss mapping to `db_unavailable` is implemented here (T-I-27 itself stays with M2.5+ and the operations table).
