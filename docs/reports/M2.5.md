## Design points
- Authorization per call through `authz.Require`, before the tree lock. Structural use cases (create, move, delete) then take `TreeLock` and reread (`GetForUpdate`, new parent, subtree size); if the node's parent changed meanwhile, the right on the new current parent is checked again.
- Cycle, parent type, inactive parent, children limit are all decided in the use case (`PlanMove`, count) before `Move`; the 23514/23503 -> not_found mapping can only fire on a real bug, as the parent is read and validated first. Name conflict on move is not pre-checked: the unique index `nodes_parent_name_key` gives `name_taken` (checked by T-I-10); the write is the only race-free check.
- 403 vs 404 for the parent: when the actor sees the node but not its parent (node is the access root), `node.move`/`node.delete` on the parent gives `forbidden` (EC-45), not `not_found`; a new parent outside the subtree stays `not_found` (EC-49).
- M2.3 open question 1: `NodeRepo.Get` still reports `AncestorsActive=false` for an inactive access root (the field itself stays conservative), but this no longer shows: the effective activity of an inactive node is false anyway, and `ActivateNode` rereads the node after the update, when the existing `tb_node_effective_active` answers correctly (own status active, so it equals the ancestors). Covered by `TestActivateAccessRootUnderInactiveAncestor`. Question 2: see above.

## Not done / deviations
- UC-N1 "row in `balances` with 0" and UC-N6 "DELETE `balances`": no table before M3.1. `DeleteStats` fills only `Children`; `Balance` and `HasOperations` are zero, the use case already calls `CanDelete` with all three, so M3 only has to extend the repository method (and create/delete the balance row).
- `ListMoveTargets` reads candidates by type (`ListActiveByType`) and filters by `Checker.EffectiveRole` in pages of 200 (one query per candidate): single source of the role rule, but O(candidates). Replace with SQL when a real tree is large.
- `ListChildren` query is matched as `strings.ToLower(TrimSpace(q))` against `name_key` (case-fold, not full Unicode fold); status filter also accepts `all`.
- Spec 09 M2.5 says "without audit"; implemented as a port with a no-op writer, as the task states.
- `AuditEntry` lives in `usecase/port` (spec 04 says `audit.Entry`); M3.3 can move it to the domain.
- Cursor is encoded in the use case (base64 of name key and id); the HTTP adapter may wrap it.
- Clock and IDGen have no production implementations yet (tests use local ones); the composition root (M4) must add them.
- `golangci-lint fmt` also reformatted a few lines of `adapter/postgres/fixture_test.go` (gofumpt).
