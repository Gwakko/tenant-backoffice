## Design decisions (RLS review facts)
- Login uses `tb_auth_user_by_email` (hash) on the pool with no transaction and no actor; if the email is unknown, the password is verified against a dummy hash made at construction by the real hasher (same parameters). Exactly one `Verify` per attempt (also for an inactive user). Only after a match does `InTx(actor = found user)` insert the refresh row.
- Refresh/Logout: `refresh_tokens` has no RLS, so `OwnerOf(hash)` runs on the pool (to pick the actor), then `InTx(actor = owner)` with `SELECT ... FOR UPDATE` by hash. Token user status and `token_version` come from `tb_auth_user_by_id` inside the same transaction (no hash).
- A replay must COMMIT the revocation: the transaction function returns nil and reports the failure through a variable. Returning the error would roll the family revocation back (the unit test `TestRefreshReuseRevokesFamily` and T-I-41 protect this).
- Password change: `tb_set_own_password(hash)`, `UPDATE users SET token_version = token_version + 1`, revoke all families of the user, in one transaction. The current hash is read through `tb_auth_user_by_email(u.email)` restricted to `u.id = tb_actor_id()`.
- Users are never inserted by this milestone (no `INSERT ... RETURNING`); ids of refresh rows are generated in the application (`IDGen`).
- Logs: only user id, ip, user agent, request id, family id. Neither passwords, tokens, hashes nor an attempted email are logged (checked in tests).
- argon2id parameters: OWASP Password Storage Cheat Sheet (https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html, fetched today) still lists m=19456 KiB, t=2, p=1 as a minimum configuration; spec value is current.

## Deviations from the spec
- Spec 04 UC-A1 says "one transaction without an actor"; the task and the RLS review require an actor for every transaction, so login opens it as the found user after the password check, and the lookups run without a transaction.
- `Login` Output contains `Session` (access, expiresIn, refresh, refreshExpiresAt, userId) plus `Email`.
- Wrong `CurrentPassword` in `ChangePassword` is `invalid_credentials` (spec 03: 401).
- A malformed refresh token in `Refresh` is `refresh_invalid`; in `Logout` it is a success.
- `Authenticate` of an expired token returns `token_expired` (EC-102); every other failure `token_invalid`.
- New `port.AuthUserRepo.ByIDInTx` (not in the spec) so that Refresh does not take a second connection while holding a transaction.
- Aud is serialised by the library as a string for a single audience; both forms verify.
