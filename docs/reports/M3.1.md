## Deviations from the spec
1. `balances`: no DELETE policy and no DELETE grant (the spec table lists four commands). A balance row goes only with its node (cascade runs with the owner's rights; tested). Same precedent as `users`. UPDATE is column-level: `amount, version, updated_at`.
2. `idempotency_keys`: no UPDATE policy and grant (spec lists four). A stored key is immutable so its hash cannot be rewritten; expired keys are deleted and inserted again (as `03` says). Policies also require an active actor with a role (`cardinality(tb_actor_scopes()) > 0`), so inactive or role-less users get nothing. Added `CHECK`s: key charset `[A-Za-z0-9_:.-]`, hash 32 bytes, `expires_at > created_at`.
3. `operations`: also immutable by trigger (BEFORE UPDATE OR DELETE and BEFORE TRUNCATE), not only by missing grants (spec 01 4.2: records are append-only). Additions: `INSERT` policy requires `actor_id = tb_actor_id()` and a visible counterparty (no existence probe through the foreign key); `CHECK counterparty_node_id IS DISTINCT FROM node_id`, `comment <= 200`.
4. `audit_log`: INSERT policy requires `actor_id = tb_actor_id()`; `TRUNCATE` trigger added; `action` and `target_type` length checks. `node_settings`: INSERT and UPDATE require `updated_by = tb_actor_id()`; per-key value `CHECK`s.
5. `tb_raise_immutable()` is created in `0005` (first user), not in `0007`; `0007` reuses it. Its Down is in `0005`.
6. Consequence for M3.3/M3.5: an UPDATE of `node_settings` must set `updated_by` to the actor (otherwise 42501), and every audit/operation row must carry the acting user as `actor_id`.

## SECURITY DEFINER (new)
| function | reads bypassing RLS | returns | why it is not a leak |
|---|---|---|---|
| `tb_settings_chain(p_node_id uuid)` | `nodes` (target and its ancestors), `node_settings`, via `tb_actor_scopes()` also `role_assignments`/`users` | rows `(source_node_id, depth, key, value)` of the chain root -> node | empty unless the target node lies in a subtree of the acting user (missing actor, inactive user, foreign, missing and ancestor nodes all give the same empty set); `source_node_id` is `NULL` for ancestors outside the actor's scopes, so a foreign node id never leaves the database; `updated_by` and `updated_at` are not returned; the values of hidden ancestors are returned on purpose (the effective value depends on them, spec 04 UC-S1); no identifier of the actor is an argument; no dynamic SQL; owner `tb_owner`, `search_path = pg_catalog, public, pg_temp`, `REVOKE ALL FROM PUBLIC`, `EXECUTE` for `tb_app` |

`tb_raise_immutable()` is a plain (not SECURITY DEFINER) trigger function; EXECUTE revoked from PUBLIC and `tb_app`.
