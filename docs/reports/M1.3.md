## Deviations
- Testkit roles: the spec says per-run random passwords via `ALTER ROLE`. That would change the passwords of the shared dev roles (breaking `make migrate` on the dev database) and race between parallel test packages. Instead testkit creates `tb_owner`/`tb_app` only if missing (no password) and the pools connect with the admin URL plus `SET ROLE tb_owner|tb_app` after connect. `current_user` is the real role, so RLS in M2 applies.
- Testkit clones one database per `NewDB(t)` call (per test) rather than per package `TestMain`; same template mechanism, simpler, still fast (~tens of ms).
- Trigger: on UPDATE where `parent_id` is unchanged the path-versus-parent comparison is skipped. During a subtree move the parent row is read from the statement snapshot with its old path, so the check would reject valid descendants. Level/type is still checked; `tb_tree_violations()` covers path consistency after the move.
- `tb_tree_violations` returns problems `level_mismatch`, `path_mismatch`, `parent_type_mismatch`.
- `migrations/embed.go` added (needed for `embed.FS`; not in the listed outputs).
- T-CI-02 uses two files (a good 0001, a broken 0002) so that "version unchanged" is observable (stays 1).
- `migrate roundtrip` uses the admin URL (superuser) on a scratch DB, so the objects are owned by the superuser; ownership is not under test.
- `go.mod`: pgx raised from indirect v5.12.0 to v5.13.0 (`00` §3.1); pgx, goose, uuid moved to direct by hand (no `go mod tidy`, as requested); run `go mod tidy` once M1.4 is merged. `uuid` is used by the schema test.
