## Done
- Domain `backend/internal/domain/report/report.go` (new package; spec 05 names `report.Sum`, `report.Date`, `report.Totals`; a domain package is the only place a port can import them from): `Sum` (signed decimal string, checked by hand: `regexp` is not on the domain allow-list), `Date` (strict `YYYY-MM-DD`, a real date), `Range` / `NewRange` (`From < To`, at most 366 days), `ParseTZ` (IANA, not empty, not `Local`, at most 64 chars), `Granularity` (`day|week|month`, empty = day), `ParseKinds`, `Period`, `Totals`, `PeriodTotals`, `ChildTotals`. Every period error is `apperr.InvalidPeriod`.
- Ports `backend/internal/usecase/port/report.go`: `ReportRepo` (`EffectiveTimezone`, `Series`, `Totals`, `Children`), `SeriesQuery`, `ChildrenQuery`, `ChildReportRow`.
- Use cases `backend/internal/usecase/report/` (`report.go`, `summary.go`, `children.go`): `SubtreeSummary` (UC-R1) and `ChildrenBreakdown` (UC-R2), each with `Input`/`Output`/`Validate()`/`Execute()`. One transaction `REPEATABLE READ READ ONLY` (`snapshotTx`) per report; `report.read` on the scope node through `authz.Require` (no role = `not_found`, role below analyst = `forbidden`); empty `tz` = effective `display_timezone` of the node (resolved inside the same snapshot). Series and totals are two separate repo calls in one transaction (the totals are a separate SQL aggregate, not a Go sum).
- Repository `backend/internal/adapter/postgres/report_repo.go`: SQL of spec 05 section 3. Boundaries are made by Postgres (`($from::date)::timestamp AT TIME ZONE $tz`), periods by `date_trunc` on the local time and `generate_series` on naive timestamps (so the DST days have 23 and 25 hours), subtree by `n.path <@ scope.path`, sums are `numeric` read as `::text` into `report.Sum`. Children: one statement per page (totals and balance of the subtree of each child), keyset `(name_key, id)`, `active` = own status AND `tb_node_effective_active(scope)` computed once. Postgres `22023` (zone unknown to the server) is mapped to `invalid_period`.
- HTTP `handlers_reports.go` (`ReportDeps`, `ReportHandlers`, `NewReportHandlers`, `ReportOperations()` = `GetSummaryReport`, `GetChildrenReport`) and `dto_reports.go`. The children cursor is bound to node, `from`, `to`, `tz`, `includeInactive` (EC-62, EC-93).

## Changes in files that existed before (what and why)

## Wiring for `app/wire.go` (M4.4 already added `LedgerHandlers`; add next to it)
```go
// import "github.com/Gwakko/tenant-backoffice/backend/internal/usecase/report"

type Handlers struct {
	httpapi.Unimplemented
	*httpapi.CoreHandlers
	*httpapi.LedgerHandlers
	*httpapi.ReportHandlers
}

// in Wire, after checker and runner exist:
rd := report.Deps{Runner: runner, Checker: checker, Reports: postgres.NewReportRepo(log)}
reports, err := httpapi.NewReportHandlers(httpapi.ReportDeps{
	Cursors: cursors, Summary: report.NewSubtreeSummary(rd), Children: report.NewChildrenBreakdown(rd),
})
if err != nil {
	return nil, err
}
// in the returned Wiring:
//	Handlers:    Handlers{CoreHandlers: core, LedgerHandlers: ledger, ReportHandlers: reports},
//	Implemented: httpapi.MergeOperations(httpapi.CoreOperations(), httpapi.LedgerOperations(), httpapi.ReportOperations()),
```
The three groups have disjoint method names, so embedding all of them at one depth is unambiguous. After this, `apitest/report_stack_test.go` can be removed and the tests can use `apitest.NewStack`; keep the two tests that build their own state.
